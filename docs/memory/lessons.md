## Harness lessons (P0)

15. `ts` can be moreutils' timestamp tool, not task-spooler. tools/dclib/queue.py accepts `ts` only if its `-h` text says task-spooler; Ubuntu's package installs `tsp`.
16. Time conversion is round-half-up in integer math (`(2*ms*fps + 1000) // 2000`); Python's round() is banker's rounding and drifts at x.5. Use only `dc time ms2frame|frame2ms`.
17. Canonical path = shortest path, then lexicographic by code point. The recon inventory broke one length tie case-insensitively (DA-Camp-Lab_M12.html vs baseline_M12_RC.html); recorded in corpus/catalog/reconcile_explained.json. Do not "fix" it twice.
18. Decoding all 121 unique media files takes on the order of 15+ minutes on 4 shared vCPUs (a 70 min 720p10 file decodes in about 2 minutes under load; 26.4 h of media in total). Run `dc ingest probe` only when no benchmark is running, or it distorts the timing numbers in budget.json.
19. Hook scripts must strip heredoc bodies before looking for violations, otherwise writing a test file that contains `rm -rf /` through a heredoc is blocked. guard_bash.py tokenises with shlex and judges only real command segments; it fails open on any parse error.
20. Several agents share one git worktree. Commit by explicit path (`git add <files>`), never `git add -A`, and never overwrite state files another agent owns (budget.json is written through harness/lib/budget_io.py with a lock).
21. A gate with no checker yet stays `pending` (not `fail`) when checked; `dc gate check` is the only path to `pass`, and only an ADR can set `waived`.
22. The render benchmark is stored under `render_bench` (swangle; `render_bench_swiftshader` for the other GL). The G0 gate and `dc state brief` once read a never-written `render_s_per_frame` key and failed. Fix: `dclib.common.render_bench_summary()` validates the real 3 compositions x concurrency 1/2/3 numbers, and render_bench.py writes a derived `render_s_per_frame` summary. A hand-typed or partial value does not satisfy the gate.
23. Limitations are recorded in harness/state/budget.json `limitations` (blocked fbaipublicfiles, Remotion Chrome host, GitHub push, no libvmaf in system ffmpeg, CPU render projection of 64.7 h swangle / 24.7 h swiftshader against a 24 h budget). G0 check `limitations_documented` lists them in its report, so they never pass silently. The render projection is a real risk for G6a/G9b; it is not waived.

## Node/fonts bootstrap (P0 fix after G0 verifier)

24. harness/setup.sh now has `node` and `fonts` sections (default `all` = apt, python, node, fonts, models, verify). `node` runs `npm ci` in studio/ keyed on the sha256 of package-lock.json (stamp studio/node_modules/.dc_lock_sha256), checks installed versions equal the exact pins, checks the browser executable named in remotion.config.ts, and runs `tsc --noEmit` (DEEP=1 also lists Remotion compositions). `fonts` copies PlexAR-*/Mono-* from the extracted archive when present, runs studio/fetch_fonts.sh, then harness/lib/check_fonts.py (22 faces parse; Arabic faces cover alef). Proven from scratch with DC_STUDIO=<copy of studio without node_modules or fonts>: npm ci plus all fonts fetched byte-identical to the committed ones, rerun skipped everything, FORCE=1 healed a deliberately broken package.

## Visual assets (P2.7, 2026-10-07)

27. The plan's keyframe filter `select='gt(scene,0.25)'` finds nothing in the Claude film (dark UI, cross-fades): over all 70:05 the full-rate scene score never reaches 0.25 (max 0.232; 168 frames > 0.02, 21 > 0.1). `dc visual keyframes` keeps the scene filter (scores recorded from 0.02, hard cuts >= 0.25 still boost priority) and finds shots from a 2 fps 160x90 gray thumbnail stream instead: settled states of the main panel (rows 14-78 %, which masks the title/progress bar, caption bar and the running timecode), thinned to >= 8 s apart. Result: 281 states -> 207 keyframes, every chapter covered (4-8 each), all JPGs verified against their thumbnail (worst mean abs diff 2.3/255). Detect costs ~10 min in one queue slot; the 121 MB thumbnail file in data/derived/keyframes/claude_film/_detect/ lets select/extract re-run without decoding again.
28. tesseract 5.3.4 (ara+eng, psm 6) reads the Claude film well only from the full 1080p frame (640-px JPGs give garbage) and runs 2x faster on the inverted (dark-on-light) image with identical text, so `dc visual ocr` grabs the film frame with ffmpeg and inverts images with mean gray < 110. NotebookLM whiteboard slides OCR noisily (median word confidence ~64); treat slide OCR as a hint for captioning, not as text truth.

## P3a audio and ASR (2026-10-07)

P3a-1. `dc q submit` RAM guard summed the declared RAM of every queued job, so a backlog of other agents' small jobs blocked any new submission (11 GB "promised" on a 15 GB box with 3 slots). It now counts only the largest `slots` queued jobs, because no more than that can be resident together. Declare honest `--mem-gb` (large-v3 int8 about 2.2 GB, turbo about 1.8 GB, MMS aligner about 3 GB).
P3a-2. Never shard a work list inside each worker from "what is still missing": shards that start later see a shorter list and skip items (16 of 71 assets were silently never profiled). `dc audio qa` now fixes the id lists per shard at submit time. Same rule for any fan-out.
P3a-3. `tsp -c <id>` follows the job's output until it ends (blocks); to peek, read the `/tmp/ts-out.*` file named in `tsp -l`. `dc q wait <id>` is the sanctioned wait. A fan-out `--prepare` must be idempotent against queue.json (labels queued/running), otherwise a refused second submit leaves duplicates.
P3a-4. ECAPA 3 s windows cluster as one speaker at cosine distance 0.6 for all S1/S2/S4 voices, and S1 vs S2 cross-similarity (0.42) is as high as S1 within itself (0.48): S1 and S2 are the same voice family. Short TTS clips (< 25 windows) can over-split (speakers=2); treat the speaker count as a proxy.
P3a-5. S2 (Esraa) is not a different script: windows at 5:00 and 40:00 fuzzy-match master.md §8 Egyptian narration (median partial ratio 100 / 93.5) at the matching chapters (CH-03, CH-22/23). It carries a loud bed (median non-speech frame -31.6 dBFS, music_bed_score 0.95). No Demucs was run on it.
P3a-6. faster-whisper turbo on S1 (initial_prompt = Latin glossary, int8, 2 threads) runs at RTF 0.92 on a busy box and writes Latin terms in Latin script most of the time; the S4 fan-out uses `dc asr submit-s4`.

## P2.5 hub harvest (context-engineer)

P2.5-1. DA_Camp_KNOWLEDGE.md has no clean heading count: CRLF payloads, headings inside fences, embedded markdown shifted to H7/H8, and an unfenced Linux guide whose shell comments look like H1. `dc corpus hub index` ignores fenced lines and accepts an H1 only with blank lines before and after (2,207 sections; the recon's 1,507 used another rule). Sections are flat; a "part" runs from one `## N · name` marker to the next.
P2.5-2. The knowledge file's crash-course listing shows only a prefix of each canvas scene and two wrong step ids (`d2`, `rec` for steps 72 and 77, nested canvas-node ids). Match by title and take full code from DA-Camp-Visual-Crash-Course.html (`VCC.step({...})`).
P2.5-3. All six top HUB builds render offline with no blocked-CDN blank (only Google Fonts is requested). The apps gate their own pictures: Lab builds put a "prerequisites not mastered" panel and a "predict before play" gate above the lab, SUPREME seals the scene until a prediction is typed. `hub_shots.py` hides the blocker, answers the gate and scrolls the canvas into view before the screenshot. Navigate with hash routes (`#<lab id>`, `#lesson/<id>`), not by clicking sidebar items (rail items are lessons that land on the gate).
P2.5-4. Headless chromium path for Playwright 1.63 here: `/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` with `executable_path=` and `--no-sandbox`. `offline=True` plus a `route("**/*")` that aborts everything not file/data/blob/about gives a hard offline guarantee.
P2.5-5. Queue: the RAM guard counts the three largest *queued* jobs, and a cancelled `tsp -r` job stays `queued` in harness/state/queue.json until the ledger is edited, so a stale 3 GB entry blocks every later submit. Submit one job per workload (`hubshots-all`, 1.8 GB) instead of one per build, and mark a removed job `cancelled` through `queue._load/_save`.
P3a-7. S4 is not one narrator: ECAPA mean embeddings split the 27 parts into voice A (S1/S2 family: P00, P00b, P02, P05, P08, P13, P15, P16, P20, P24), voice B (S3 TTS family: P03, P04, P06, P07, P09-P12, P14, P17-P19, P21-P23, P25) and voice C (P01, closest to the English S5). Within one part there is always one speaker (corpus/audio/voices.json).
P3a-8. Chapter windows for forced alignment must come from the ASR, not from the nominal timetable. Aligning each chapter in its nominal window +-2 s let neighbouring speech leak in (CH-10/CH-11 overlapped by 3.9 s, first word 'SQL' sat on the previous chapter's last words). `dc align scripted` now matches script to whisper words and cuts at the midpoints of the pauses between chapters: zero overlaps, 37 of 37 chapters inside their nominal windows.
P3a-9. CTC parks letters with no acoustic evidence (silent final alef of 'نجحوا', swallowed letters) in the nearest pause, which stretched words to 4-9 s. Trim edge chars with posterior < 0.2 or stranded > 0.35 s from their neighbour (align.word_span) and drop the silent alef in the alignment surrogate. Word duration now peaks at 1.5 s (median 0.30 s).
P3a-10. faster-whisper word timestamps are not a second aligner for the 120 ms test: against Silero speech onsets whisper starts are +219 ms late (5 % within 120 ms) while MMS is -22 ms (65 % within 120 ms, 95 % within 250 ms). A real second CTC model (e.g. an Arabic wav2vec2 fine-tune from huggingface.co) is needed for the G3 agreement number.
P3a-11. turbo vs large-v3 on S1: the turbo deficit is mostly Latin terms (errors on 62 % of Latin tokens vs 36 %), not Arabic words (15.3 % vs 12.3 %). Greedy decoding does not speed up large-v3 (encoder-bound, about 20 %). Segment avg_logprob is useless as an error flag on clean reads (corr -0.10).

## P2 text, retrieval and maps (context-engineer, 2026-10-07)

P2.1-1. SRT files in the archives are not uniform: LMArena `_captions_ar*.srt` have no blank line between cues, so a blank-line splitter returned the whole 87 KB file as one 59,858-char chunk. `distill.parse_cues` scans line by line (a time line starts a cue; the next bare integer followed by `-->` ends it). Always check `max(len(text))` of chunks after a distill run.
P2.1-2. Egyptian prose carries so many Latin terms that the Arabic share of letters is 0.3-0.5 for entirely Arabic narration; a 0.5 threshold labelled 70 % of the Arabic masters `en`. Threshold is 0.3 (`ar-EG`), and `lang_mix` is set between 0.1 and 0.9.
P2.1-3. The knowledge file is 80 % verbatim payload (JSON/JS/CSS dumps under `▸ \`file\`` headings). Chunking all of it gives about 35k chunks of noise; `distill` keeps the first 3 chunks of each payload section (flag `payload`) and 6,238 chunks cover the readable rest. Read the full section with `dc corpus show K#####` (byte span via knowledge_index).
P2.1-4. BM25 needs only 5 s and 10 MB for 15k chunks, so there is no reason to keep a daemon. Near-duplicate masters (28-min merged source, NotebookLM visual masters in EN and AR, Unified Master, master.md) dominate the top hits; search keeps at most 2 hits per document. The `specific part` rank in reports/retrieval_smoke.md shows where the NotebookLM part of the topic lands.
P2.1-5. bge-m3 on CPU is about 0.44 chunks/s on one thread under load (load 16 s, RSS about 2.5 GB). Embedding all 15k chunks would take 9 h of one thread; the default dense subset is the 2,928 core chunks (NotebookLM parts, narration, TTS texts, notes, JSON/CSV, master.md + Unified Master) at max_len 192. The model dir has no `2_Normalize`, so load it with transformers (`AutoModel`, CLS pooling, L2 normalise), not sentence-transformers.
P2.1-6. The queue RAM guard counts the three largest *queued* jobs, so a 24-job ASR fan-out (1.8 GB each) promises 5.4 GB and refuses any later 3.5 GB job even though 8.7 GB is free. Submit big-model jobs before a long fan-out, or wait for the backlog; do not shrink the declared `--mem-gb`.
P2.7-1. Caption agents wrote `"` inside the `layout` string (`title + "3" number`), making 4 of 752 lines invalid JSON. `dc visual merge` escapes inner quotes by field order and lists the repaired lines in reports/visual/missing.md; it never drops a line silently. Ask caption agents to avoid double quotes in free text.

## G2 verifier fixes (2026-10-07)

G2-1. A caption that says `caption_src: vision` proves nothing: 30 busy slides (95 % coverage grid, fan-out chart, 66.67 % callback) were captioned "blank / corrupted" because the captioner read the noisy OCR, and 8 records copied OCR fragments into `numbers_seen`. `dc visual audit` (tools/dclib/visual_audit.py, used by G2 `visual_captions_match_pixels`) now rejects a blank/corrupt/illegible whole-image claim when the picture has ink (> 0.3 % of pixels away from the background), OCR text or recorded text/numbers, and rejects any numbers_seen entry that no recorded text backs (numbered-card runs 1..n excepted). On the old assets.jsonl it flags 22 false blank captions and 40 records with unbacked numbers.
G2-2. Corrections to captions live in corpus/visual/recaptions.jsonl (schema visual_recaption, 168 records, `reviewed: pixels`), not in data/derived/visual/captions/: `dc visual merge` lays them over the batch captions, so a re-run of the merge keeps them and git carries them. Numbers read from the pixels are also appended to `text_seen` ("numbers on slide: ...") so the audit can tie each number to a recorded text.
G2-3. NotebookLM numbers use comma thousands ('1,250,000'); master.md uses space thousands. NUM_RX now accepts both, and a Latin digit right after an Arabic tatweel ('لـ10,000') is a number start. G2 `canon_numbers_faithful` re-checks that no comma group is split and every listed number occurs in its scene text (old canon: 56 split fragments).
G2-4. Markdown tables escape a literal pipe inside a cell as `\|`; `canon_md.split_cells` unescapes it (also inside backticks) and G2 fails if a backslash-pipe survives in chapters.json or glossary.json.

## P3b alignment tooling (transcription-aligner, 2026-10-08)

P3b-1. **MMS emission framing bug (fixed).** `harness/lib/align.py:emissions` trimmed `context` frames from each end of every 30 s window, but the wav2vec2 conv stack emits floor((n-400)/320)+1 frames (1699 for 34 s), so each window kept 1499 instead of 1500 frames and the concatenated timeline ran early by 20 ms per 30 s (up to 0.4 s per 10-min emission block, a 40 ms/min sawtooth). The first S1 alignment carried that error; the symptom was the whisper-vs-MMS offset sliding from +60 to -300 ms inside every block and 20 s of "unexplained" VAD speech. Now `lg[:, fc:fc+1500]`. After the fix and a full S1 re-run (ids unchanged): MMS onset vs Silero 93.9 % within 120 ms (was 65 %), unexplained VAD speech 1.1 s (was 20.3 s), whisper-vs-MMS 74.8 % within 120 ms (was 45.7 %). Always check a new emission path with a per-position drift table (aligner minus an independent timer, binned by position in the block).
P3b-2. Two-aligner agreement (G3): MMS-300m vs wav2vec2-large-xlsr-53-arabic on the same S1 tokens and windows: 97.9 % of 6644 words within 120 ms (Arabic-script words 98.2 %, Latin-containing words 96.5 % with crude letter mapping), median |diff| 0 ms, p99 180 ms. The two models are both wav2vec2-family CTC models trained on overlapping XLSR data, so agreement shows the framing and trimming are sound, not that both are right to the millisecond; the Silero onset check (P3b-1) is the independent acoustic reference.
P3b-3. A regex character class typed with Arabic characters can silently cover all letters: `[ؐ-ًؚ-ٰ...]` written from memory spanned U+0610-U+064B and deleted every Arabic letter. Write ranges as \uXXXX escapes and test that a normal word survives (a test of the form "all chars in vocab" passes on an empty string).
P3b-4. S2 (music bed) aligned as well as S1 with MMS on the raw audio (median conf 0.806 against 0.826, every chapter above 0.7): the bed is quiet and the tracks share the voice family, so Demucs was not needed. S2 chapter starts sit 0.1-5.9 s before the nominal master section 7 boundary (the centre of the longest VAD gap is used), and word starts differ from S1's by -4.7..+8.2 s (median +0.26 s): S2 is a separate reading, not a re-timed copy.
P3b-5. S5 English with MMS 'eng': the script is its own romanisation, median char posterior 0.997. Caption k of cues_70m05.json starts at the cumulative count of alignable tokens (`AL.tokenise` of the caption text), not at the caption's `words` field, which also counts standalone dashes.
P3b-6. Parallel queue jobs that update corpus/audio/assets.json raced on read-modify-write; `audio.set_alignment` now takes a file lock (data/derived/audio/assets.lock).
