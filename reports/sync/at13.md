## 3. Boundary flags and re-pick rule
Flag (applied to all 29 events): expected frame or raw onset within 3 f of a shot cut frame (cuts: S02 218, S03 479, S04 709, S05 913; S01 starts at 0; cut = first word of the shot's first sentence - 5 f, as in resolve.ts). Flagged: events 8 and 14 only. S04/S05 cuts have no event within 3 f.
Re-pick trigger: raw onset <= cut frame + 1. Both flagged events have raw onset exactly on the cut frame (step d=2.43 and 5.79, the whole table entering), i.e. the detector measured the cut.
- Rule B (primary): ignore frames <= cut; require one post-cut baseline frame; onset = first k >= cut+2 in the window with d[k] >= 0.05 and d[k] > 2 x max(d[cut+1..k-1]) (a spike that exceeds the shot-entry transient). Gives 221 (0 f) and 483 (+1 f), matching the earlier p7 manual re-picks.
- Rule A (sensitivity): mask the cut frame only and keep the original detector. Gives 219 / 480 (-2 f). Frames cut+1..cut+3 hold a continuous 0.4-0.6 entry transient of the table (no camera/FX), so a 0.05 threshold fires on the transient, not the event.
- Caveat: rule B was defined after seeing these two events (it reproduces the p7 manual re-picks, which preceded this run). It was applied to the flagged set by one criterion, and it never fired on a non-flagged event. The verdict depends on it: a stricter reading (raw, or rule A) FAILs the -1 f clause. Both events are real table events whose true onsets sit inside the entry transient, so 3-frame ambiguity is inherent; an unambiguous test needs a non-cut render (e.g. `--nocut` with a hold before the anchor).
